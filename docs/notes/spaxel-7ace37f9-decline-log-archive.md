METRIC SUITABILITY — verified from IDF source, and CORRECTING an initial wrong read
firmware/main/websocket.c:572 reports esp_get_free_heap_size(). In ESP-IDF 5.2 that is heap_caps_get_free_size(MALLOC_CAP_DEFAULT) (esp_system/port/esp_system_chip.c:71-74). PSRAM is registered into the heap allocator with caps MALLOC_CAP_SPIRAM | MALLOC_CAP_DEFAULT (esp_psram/esp_psram.c:305,315), and it is added under SPIRAM_USE_MALLOC — the mode HEAD resolves to. Therefore free_heap_bytes DOES include the PSRAM pool under the current config, and the metric is suitable for the intended measurement. I first suspected it was internal-only (MALLOC_CAP_INTERNAL|MALLOC_CAP_8BIT, which is esp_get_free_internal_heap_size) — that is wrong for this call site; recorded so nobody re-derives the wrong conclusion.

CONFIG FINDING: HEAD sdkconfig.defaults sets all three SPIRAM_USE_* choice symbols simultaneously (MEMMAP :126, CAPS_ALLOC :127, MALLOC :128) — invalid for a Kconfig choice. Verified harmless in practice: Kconfig resolves it deterministically to CONFIG_SPIRAM_USE_MALLOC=y and explicitly clears MEMMAP and CAPS_ALLOC (confirmed in the generated sdkconfig).
